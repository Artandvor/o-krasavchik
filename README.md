# О!дин шаг — «Сначала закат. Потом отель.» (трек «О!дин шаг до идеального отеля»)

Агентная система для Островка: из открытых данных вычисляет, что увидит и услышит гость **из конкретного окна**.
Это вид на море, закат и горы по датам, ночной шум у каждой стороны здания, реальный путь к пляжу
с переходами через железную дорогу. Отельеру система задаёт только нужные вопросы, а гость ищет не отель,
а момент: «хочу смотреть, как солнце садится в море». Регион — Адлер (Сочи), 230 отелей.

## Быстрый старт

```bash
git clone <URL репозитория>
cd <repo>
cp .env.example .env   # необязательно: без него всё работает (LLM выключена, разбор по правилам)
docker compose up --build
# открыть http://localhost:8080
```

Без Docker: `pip install -r requirements.txt && PORT=8080 python run.py`.

Для разработки: `cp docker-compose.override.yml.example docker-compose.override.yml` — код монтируется
в контейнер, сервер перезапускается при изменениях. CI (`.github/workflows/ci.yml`) гоняет тесты
и `docker compose up --build` с проверкой `/health`.

## Зависимости и переменные окружения

Рекомендованные ресурсы: 2 CPU, 2 GB RAM, ~1 GB диска под образ. Сборка образа — 2–4 минуты
(на Apple Silicon дольше из-за `platform: linux/amd64`).

Внешних сервисов нет: база — SQLite-файл внутри контейнера, демо-данные лежат в репозитории.
LLM необязательна; подключается любая OpenAI-совместимая или Anthropic API.

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `PORT` | `8080` | порт приложения внутри контейнера |
| `HOST` | `0.0.0.0` (в Docker) | адрес, на котором слушает приложение |
| `ODIN_DB` | `/app/var/odin.sqlite` | рабочая база; при первом старте копируется из `data/odin-demo.sqlite` |
| `LLM_PROVIDER` | `none` | `none` \| `openai` (любой OpenAI-совместимый) \| `anthropic` |
| `LLM_API_KEY` | — | ключ LLM |
| `LLM_MODEL` | `gpt-4o-mini` / `claude-sonnet-4-5` | модель |
| `LLM_BASE_URL` | — | для OpenAI-совместимых: OpenRouter, Ollama, vLLM |
| `ODIN_DATA`, `ODIN_REGION` | `./data`, `./config/region.json` | пути к данным и описанию региона |

## Сидирование

Демо-данные уже в репозитории: `data/processed/` (растры 10 м, здания, пешеходный граф, отели)
и `data/odin-demo.sqlite` (факты по 230 отелям, вопросы и ответы отельеров, противоречия, демо-запросы).
При старте контейнера они подключаются автоматически, ничего делать не нужно.

Пересобрать данные с нуля из открытых источников (нужен интернет, ~15 минут):

```bash
make seed        # = docker compose --profile pipeline run --rm pipeline
make test        # 15 тестов на синтетическом берегу с известной правдой
```

## Маршруты и доступ

- `/` — интерфейс с переключателем трёх ролей в шапке; авторизации в прототипе нет:
  - `#/guest` — **гость**: предвкушение → «окна» → смакуем окно (время дня, этаж, сторона) → бронь окна → «Совпало?» после поездки;
  - `#/host/<id>` — **отельер**: сильные стороны против соседей, 3 вопроса в один клик, что ищут гости, подтверждение фактов, споры;
  - `#/ops/<раздел>` — **Островок**: покрытие, очередь противоречий, характеристики (новая — текстом), качество и разметка вслепую, «что если построят дом», журнал агентов.
- `/health` — `200 {"status": "ok", "hotels": 230}`
- API: `/api/search?q=…&month=7`, `/api/panorama/{id}?floor=&date=`, `/api/hotels/{id}`, `/api/guest/feedback`,
  `/api/hotelier/{id}`, `/api/hotelier/{id}/insights`, `/api/questions/{id}/answer`, `/api/conflicts`,
  `/api/characteristics/compile`, `/api/whatif/building`, `/api/metrics`, `/api/labels/queue`, `/docs` (Swagger)

## Как это соответствует заданию

| Задача | Решение |
|---|---|
| Сбор, хотя бы одна по геоданным | 21 характеристика, 11 инструментов агента. Вид на море, закат и горы — лучевой анализ по рельефу Copernicus DEM и зданиям OSM; у 65% зданий нет высоты, поэтому считаем **48 сценариев высот** (Монте-Карло), и уверенность — это доля сценариев. Солнце — алгоритм NOAA на конкретную дату. Шум — модель по каждой стороне здания. Пляж — маршрут по пешеходному графу с рельефом (Тоблер) и переходами через ж/д и трассу |
| Агент сам решает, откуда брать | Спецификация характеристики называет инструмент; агент проверяет свежесть, вызывает инструмент, при отсутствии данных переключается на запасной источник (берег вместо пляжа и т. п.), сводит источники и решает, спрашивать ли отельера. Всё пишется в журнал |
| Диалог с отельером | Вопросы ранжируются по ценности: спрос гостей × неуверенность × «источники спорят», бюджет 3 на отель. Где есть расчёт — гипотеза на подтверждение в один клик. Свободный ответ раскладывается по полям (LLM или правила). Отельер имитируется |
| Источник, уверенность, дата, противоречия | У каждого факта: источник, метод с версией, уверенность, дата, срок годности. Противоречие → уверенность падает, конфликт в очередь, расчёт на перепроверку. Соседние классы («тихо» и «умеренно») — не противоречие |
| Расширяемость | Характеристика — YAML в `characteristics/`. Новую можно описать текстом: «кофейня в 5 минутах пешком» → `poi_nearby` с тегами OSM → проверка на отелях → сбор по всем |
| Поиск по запросу | Разбор в критерии с учётом месяца поездки, подбор **стороны и этажа**, где все «оконные» желания сбываются одновременно, текст просьбы к отелю |
| Объяснение, сравнение, кабинет, актуализация, метрики | «Твой день здесь», «Почему мы уверены», «Где можем ошибаться». Кабинет отельера. Сроки годности по характеристикам и сценарий «рядом построили дом». Покрытие, доля вопросов, точность и калибровка по разметке вслепую |
| Сверх задания | **Гость как источник правды**: после поездки «Совпало?» — ответ становится фактом с высоким доверием и запускает перепроверку |

## Структура

```
app/geo/        prepare (растры, граф), view (видимость + Монте-Карло, панорама), noise, walk, sun
app/tools.py    инструменты агентов
app/agents/     collector, hotelier (вопросы, разбор, симулятор), search, compiler, refresher
app/truth.py    сведение источников и конфликты
app/store.py    SQLite: факты с историей, конфликты, вопросы, журнал, разметка
app/static/     интерфейс: window.js рисует вид из окна по данным, app.js — три роли
characteristics/*.yaml   реестр характеристик
scripts/        fetch_data (сырые данные), prepare_region, run_agents
tests/          синтетический берег с известной правдой
docs/           план, источники, дизайн
```

## Ограничения (честно)

Деревьев нет в открытых данных, поэтому вид может быть хуже расчётного; это учтено в уверенности
и закрывается отельером, гостем и разметкой. Шум — модель, а не замер. Этажность у 30% отелей оценена.
Каталог отелей взят из OSM; в реальной интеграции координаты и контуры придут из базы Островка.
