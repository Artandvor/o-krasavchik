# План, источники и решения

## Ключевые решения

В задании сказано: *«основная сложность — не придумать характеристику, а достоверно её
получить»*. Поэтому ставка такая:

1. **Регион с настоящей болью — Адлер.** Рельеф, море, горы, железная дорога вдоль берега,
   аэропорт под боком. «200 м до пляжа» здесь часто значит «через пути и трассу».
2. **Уверенность вычисляется, а не назначается.** Монте-Карло по неизвестным высотам
   зданий, штрафы за качество данных, калибровка по разметке.
3. **Детализация до стороны и этажа.** Не «в отеле есть вид», а «закат из окон СЗ стороны
   с 4-го этажа, май–авг», плюс готовый текст просьбы к отелю. Это прямо бьёт в метрику
   отмен Островка.
4. **Вопросы отельеру по ценности информации.** Гипотеза на подтверждение в один клик,
   максимум 3 вопроса на отель.
5. **Новая характеристика текстом вживую на защите.**

## Ресёрч источников (что проверено и выбрано)

| Задача | Источник | Почему он | Ограничения |
|---|---|---|---|
| Отели, здания, дороги, ж/д, пляжи, POI | OpenStreetMap / Overpass API (зеркала: overpass-api.de, maps.mail.ru, kumi) | единственный открытый полный слой; у объектов есть дата правки → свежесть | высоты зданий заполнены частично; часы работы есть не везде |
| Рельеф | Copernicus DEM GLO-30, AWS Open Data, без ключа | лучшая открытая точность (30 м), покрывает Кавказ | это DSM (с застройкой и лесом): строим DTM морфологическим открытием, а «горб» DSM−DTM используем как подсказку высоты зданий |
| Запасной рельеф | Open-Meteo Elevation API (GLO-90) | без ключа, 100 точек за запрос | 90 м |
| Солнце | алгоритм NOAA (свой код, ~0.5°) | без зависимостей | рефракция учтена грубо |
| Климат | Open-Meteo Historical (ERA5) 2016–2025 | бесплатно, без ключа | сетка ~10–25 км |
| Температура моря | Open-Meteo Marine | там же | 2023–2025 |
| Воздух | Open-Meteo Air Quality (CAMS) | там же | модельные данные |
| Шум | своя модель по классам дорог / ж/д / заведениям / ВПП | открытых шумовых карт по РФ нет (END-карты только в ЕС) | это модель, а не замер: уверенность ≤ 0.65, отельер может поправить |

Рассмотрены, но не взяты в прототип: OpenCellID (нужен ключ), Mapillary и Wikimedia
Commons (фото — следующий шаг для независимой проверки вида), GTFS Сочи (открытого фида нет),
порталы стройразрешений Сочи (нет машиночитаемого API).

## Архитектура

```
 характеристика (YAML) ──► агент-сборщик ──► инструмент (viewshed / noise / walk / poi / …)
                               │                    │
                               │                    ▼
                               │              факт: значение, область (сторона/этаж),
                               │              источник, метод, уверенность, дата, TTL
                               ▼
                         сведение источников ──► конфликт? ──► вопрос отельеру (VOI, бюджет 3)
                               │                                  │ ответ свободным текстом
                               ▼                                  ▼
                          поиск по запросу ◄──── факт «отельер» ◄─ разбор по полям
                               │
                               ▼
               ранжирование + «какой номер просить» + объяснение + текст просьбы
```

## Ограничения

* Деревья не учитываются: в открытых данных их нет, и вид может быть хуже расчётного.
  Учтено снижением уверенности и вопросом отельеру.
* Этажность неизвестна у части отелей: считаем до 9 этажа и помечаем.
* Шум — модель: относительное сравнение сторон надёжнее абсолютных децибел.
* Каталог отелей — из OSM, а не из Островка: в реальной интеграции координаты и контуры
  берутся из базы Островка, а остальной конвейер тот же.

## Что дальше

* Независимая проверка вида по геофото (Mapillary, Wikimedia Commons) как второй источник.
* Высоты зданий из теней на спутниковых снимках или из Overture Maps.
* Активное обучение: какие отели размечать следующими (максимальная неуверенность).
